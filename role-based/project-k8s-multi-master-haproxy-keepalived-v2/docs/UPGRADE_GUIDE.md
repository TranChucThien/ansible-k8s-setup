# Kubernetes Upgrade Guide\n\nThis guide covers upgrading Kubernetes masters in the multi-master HA cluster.\n\n## Overview\n\nThe upgrade process uses Ansible automation to safely upgrade Kubernetes masters one by one, ensuring cluster availability throughout the process.\n\n## Upgrade Methods\n\n### 1. Automated Upgrade (Recommended)\n\n#### Basic Upgrade\n```bash\n# Upgrade all masters sequentially\nansible-playbook -i inventories/myenv/hosts.ini playbooks/site-upgrade-masters.yml\n```\n\n#### Complete Upgrade with Backup\n```bash\n# Includes ETCD backup and comprehensive verification\nansible-playbook -i inventories/myenv/hosts.ini playbooks/site-upgrade-masters-complete.yml\n```\n\n### 2. Manual Upgrade\n\nFor detailed manual upgrade steps, see [Manual Upgrade Guide](MANUAL_UPGRADE_MASTERS.md).\n\n## Configuration\n\n### Set Upgrade Version\n\nEdit `inventories/myenv/group_vars/all.yml`:\n\n```yaml\n# Kubernetes upgrade configuration\nkubernetes_upgrade_version: \"1.34\"        # Major.minor version\nkubernetes_target_version: \"v1.34.3\"      # Full target version\nkubernetes_package_version: \"1.34.*\"      # Package version pattern\n```\n\n### Upgrade Process Logic\n\nThe automation automatically determines the upgrade method:\n\n- **First Master**: Uses `kubeadm upgrade apply v1.34.3`\n- **Additional Masters**: Uses `kubeadm upgrade node`\n\n## Pre-Upgrade Checklist\n\n- [ ] **Backup cluster**: Run ETCD backup before upgrade\n- [ ] **Check cluster health**: Ensure all nodes are Ready\n- [ ] **Verify resources**: Ensure sufficient disk space and memory\n- [ ] **Review compatibility**: Check Kubernetes version compatibility matrix\n- [ ] **Test in staging**: Perform upgrade in non-production environment first\n\n## Upgrade Features\n\n### Automated Safety Measures\n\n- **Serial execution**: Upgrades one master at a time\n- **Health checks**: Verifies cluster health before proceeding\n- **Preflight bypass**: Handles common preflight check issues\n- **Service restart**: Properly restarts kubelet after upgrade\n- **Version verification**: Confirms successful upgrade\n\n### Error Handling\n\n- **Ignore preflight errors**: Bypasses CreateJob timeout issues\n- **Cleanup old jobs**: Removes stuck upgrade health check jobs\n- **Graceful failures**: Continues with warnings for non-critical issues\n\n## Verification\n\nAfter upgrade, the automation verifies:\n\n1. **Node status**: All masters show Ready status\n2. **Component versions**: API server, controller-manager, scheduler versions\n3. **VIP access**: Virtual IP responds to health checks\n4. **Control plane pods**: All control plane pods are running\n\n## Troubleshooting\n\n### Common Issues\n\n**Health check timeout**:\n```bash\n# Check for stuck jobs\nkubectl get jobs -n kube-system\n\n# Clean up if needed\nkubectl delete jobs -n kube-system -l job-name=upgrade-health-check\n```\n\n**Version mismatch warnings**:\n- Normal during upgrade process\n- Resolves after all masters are upgraded\n\n**Upgrade fails**:\n```bash\n# Check kubelet logs\nsudo journalctl -xeu kubelet\n\n# Verify etcd health\nkubectl get pods -n kube-system -l component=etcd\n```\n\n### Recovery\n\nIf upgrade fails:\n\n1. **Check logs**: Review Ansible output and kubelet logs\n2. **Verify cluster**: Ensure cluster is still functional\n3. **Rollback if needed**: Restore from ETCD backup if necessary\n4. **Retry**: Fix issues and retry upgrade\n\n## Best Practices\n\n- ✅ **Always backup before upgrading**\n- ✅ **Upgrade one minor version at a time**\n- ✅ **Test in non-production first**\n- ✅ **Monitor cluster during upgrade**\n- ✅ **Verify each master before proceeding**\n- ✅ **Keep upgrade logs for troubleshooting**\n\n## Version Support\n\n| Current | Target | Supported |\n|---------|--------|-----------|\n| 1.33.x  | 1.34.x | ✅ Yes    |\n| 1.32.x  | 1.34.x | ❌ No     |\n| 1.34.x  | 1.35.x | ✅ Yes    |\n\n**Note**: Kubernetes only supports upgrading one minor version at a time.\n\n## Post-Upgrade Tasks\n\n1. **Update workers**: Upgrade worker nodes after masters\n2. **Update CNI**: Check if Calico needs updating\n3. **Update add-ons**: Verify all cluster add-ons are compatible\n4. **Test workloads**: Ensure applications work correctly\n5. **Update documentation**: Record upgrade completion and any issues
